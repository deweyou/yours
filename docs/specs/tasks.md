# 独立任务：功能讨论稿

状态：独立任务 MVP 已接入，完整方向仍在迭代。更新日期：2026-10-27。下方 C1–C29 是产品决定，不表示所有条目已实现；本期范围与验证边界见下一节。

本文件维护用户已确认方向、暂定取舍与未决问题。竞品研究见[任务产品研究](../research/task-apps.md)；研究建议不能自动升级为已确认决定。

## MVP 范围与实现边界

用户已选择先实现可运行 MVP，通过实际使用继续收敛细节，暂停穷举边界问题。

- 已接入：All / Today / Inbox / 项目 / 已结束 / 回收站；快速新建、大纲与侧边详情、原生富文本备注、任意层级子任务、移动、三种状态及父子联动；统一时间安排（仅日期/起止时段/多段）、独立的仅日期 DDL、可选本地提醒；正常保存/重启恢复和 15 天回收站保留。
- 宽屏常驻任务导航，All 按项目显示可展开子任务的大纲，点击标题文字原地编辑、点击行内空白或行尾图标打开可关闭的侧边详情；主列表与详情内子任务一致，Return/失焦保存、Escape 取消，编辑标题保留当前详情；窄屏收起导航或列表。详情顺序为标题、紧凑属性条、子任务、备注；时间与截止共用自绘月历浮层，紧凑平台沿用系统自适应呈现。属性条显示首段摘要、其余安排数量、独立截止和提醒，添加入口使用加号菜单；明确动作使用带 Tooltip 和无障碍名称的图标按钮，属性值与确认按钮保留文字。多级文件夹、复杂筛选、手动排序与进度展示留待下一轮。项目本期只提供创建与作为移动目的地，暂不提供删除/归档/改名。
- 暂缓：重复任务、预计时长及汇总、文档 Todo 聚合。这些已确认方向不推翻，也不把相关条目称为已实现。
- 三态、只读、移动、软删除和恢复由 `TodoLibrary` 统一执行；状态操作可通过 UndoManager 撤销。撤销按受影响字段恢复并保留其他后续编辑；同一字段或层级约束冲突时保留当前内容并提示，不静默覆盖。
- Today 命中仅日期安排、当天 DDL 或与当天相交的执行时段，同一任务只显示一条。当前没有冻结临期/积压的独立分栏。
- 15 天从删除时刻起按 15 × 24 小时计算；启动载入、任务页存在时每 30 秒及恢复前检查，不依赖后台常驻。到期清除任务内容，仅保留同步去重所需身份标记，应用内不能恢复；离线旧副本在合并时受删除标记约束。
- 恢复时原父任务不存在或位于不做了的只读分支，则恢复到原项目顶层；项目不存在则进 Inbox。可接收的已完成父任务遇到未完成子任务时按祖先恢复规则重新打开。
- 任务进入现有保存及可选 CloudKit 快照同步。同一任务并发冲突暂停并保留两端，不自动覆盖，尚无冲突解决 UI；真实设备任务同步未验收。详见[存储与同步](../storage-and-sync.md)。
- 本地验证包括 Swift 行为/持久化/同步替身测试、macOS 与 iOS Simulator 构建及 Mac 隔离预览。触控、真实输入法候选、VoiceOver 和真实 CloudKit 不由这些结果替代，验收方法见[验证](../verification.md)。

## 后续设计边界

先确定独立任务的功能逻辑，再讨论页面与交互，最后进入实现。文档内 Todo 的提取、汇总、双向关联，以及「文档是否为根任务」留待后续单独设计；当前不据此改写文档模型。

## 已确认方向

| 编号 | 决定 | 边界 |
| --- | --- | --- |
| C1 | 任务有任务名/标题，可有子任务和富文本备注 | 富文本复用 Yours 的编辑能力方向；具体支持内容和呈现方式未定 |
| C2 | 父任务必须由用户手动勾选完成 | 所有子任务结束不自动完成父任务；勾父时对未完成后代的处理见 C13 |
| C3 | 按项目组织任务，支持多级文件夹 | 项目、文件夹、清单的确切关系和操作仍需收敛 |
| C4 | 一个任务可设置多个不连续执行时段 | 不通过复制同名任务或重复任务代替多时段；时间段结束不自动完成任务 |
| C5 | 可整体安排父任务，也可分别安排子任务；父任务可设 DDL | 子任务不需要为成为任务而强制设时间；父子同时安排时的汇总算法未定 |
| C6 | 重复任务采用不累积方式 | 本次未完成时不因周期到来不断增加未完成项；当前子任务进度不能因此自动重置 |
| C7 | 支持固定周期与完成后间隔两种重复 | 前者有日历锚点，后者依据本次完成计算；漏期、提前完成等细节见未决项 |
| C8 | 数据保存与同步对齐文档 | 本地优先、生产/开发/测试隔离、可选 CloudKit；现有同步实现不能视为已支持任务 |
| C9 | 保留备注检查项与结构化子任务两种用途 | 备注检查项仅在正文中勾选，不计入任务进度；子任务可独立安排时间。具体进度算法与页面呈现未定 |
| C10 | 子任务不限制嵌套层数，每一级都有完整任务能力 | 深层浏览与折叠方式留待交互设计；父子重复规则如何协调仍需单独确定 |
| C11 | 移动任务携带全部后代，子任务跟随父任务的项目归属 | 移到另一父任务下时重挂完整子树；移到项目顶层时解除原父关系；单独跨项目移动时成为目标项目顶层任务。禁止移到自己或自己的后代下 |
| C12 | 任务有「未完成」「已完成」「不做了」三种状态 | 「不做了」保留为任务状态，与删除区分；进度计算见 C17，恢复见 C15–C16，影响重复推进的规则仍需确定 |
| C13 | 完成父任务前，所有后代必须处于「已完成」或「不做了」 | 若仍有未完成后代，弹窗让用户选择将剩余项全部完成、全部设为不做了，或返回逐项处理；不默认批量完成。已结束项保持原状态，逐项处理或取消时不提前提交父任务完成 |
| C14 | 父任务设为「不做了」时，直接将所有未完成后代一并设为「不做了」 | 不额外弹确认；已有完成记录和原本「不做了」的后代保持不变 |
| C15 | 撤销结束操作与重新打开任务采用不同恢复规则 | 撤销刚才的完成/不做了操作，精确恢复操作前受影响任务的状态；以后重新打开只将当前任务设为未完成，后代保持各自状态。重复推进和跨设备并发下的撤销边界仍需另定 |
| C16 | 单独恢复子任务时，已结束的祖先一并恢复为未完成 | 保持未完成子任务的祖先链未完成；不改写其他后代或兄弟任务的状态 |
| C17 | 进度计算排除「不做了」的任务 | 分子为已完成数量，分母为已完成与未完成数量之和；「不做了」不计入分子或分母，计算上视同移除但保留记录。统计层级见 C18；分母为零时的呈现仍需确定 |
| C18 | 多级子任务进度打平到最末级任务统计 | 递归统计子树中没有子任务的末级任务，中间父任务不重复计数，各项等权；「不做了」按 C17 排除。例如功能设计已完成，实现下的数据模型已完成、页面未完成，则总进度为 2/3。进度不自动改变父任务状态 |
| C19 | 「不做了」的任务及其整棵分支只读，不可继续编辑或添加子任务 | 保留已有完成后代的状态与记录，但受不做了祖先约束仍为只读；要修改其中任务，先显式恢复它，并按 C16 恢复已结束祖先。移入任务等结构操作边界仍需确定 |
| C20 | 已完成任务允许继续编辑；添加子任务后恢复为未完成 | 修改已有标题、备注或时间不自动改变完成状态；新增未完成子任务后，当前任务及已结束的祖先按 C16 恢复为未完成，其他后代状态保持不变 |
| C21 | 删除任务时，连同所有后代一起移入回收站，恢复时整棵还原 | 保留内容、层级、各自状态和时间安排；恢复不统一重置为未完成。保留期限见 C22，恢复位置见 C23；原位置存在但不可接收、重复与通知行为仍需另定 |
| C22 | 回收站软删除保留 15 天，到期硬删除且无法恢复 | 保留期从删除时起算；到期永久移除对应任务及随其删除的后代。时间边界、离线设备清理与同步删除的技术机制待设计，不能只隐藏入口而继续提供应用内恢复 |
| C23 | 恢复优先回到原位置，原位置不存在时逐级降级 | 原父任务不存在但项目仍在时，作为该项目顶层任务恢复；原项目也不存在时恢复到 Inbox。携带完整子树，不自动恢复其他已删除任务或项目，并告知实际恢复位置；原父任务仍存在但已结束/只读的处理仍需结合状态规则确定 |
| C24 | 任务支持无安排、仅计划日期，以及一个或多个具体执行时段 | 仅计划日期不要求具体时刻；DDL 独立保留，可以与计划日期不同。统一为安排条目，默认选日期，可补充起止时间及独立提醒，再添加更多条目；截止日期单独保留 |
| C25 | 计划日期用于对应日期的 Todo list 展示，DDL 用于判断正式逾期 | 未完成任务的计划日期已过，属于计划未完成，不因此判定正式逾期；执行时段结束不自动完成任务。DDL 已过且仍未完成才算正式逾期；不自动将旧计划日期改成今天，保留原安排且仍可找到 |
| C26 | 日清单包含当天计划与当天截止任务，并支持查看近期截止任务 | 只有 DDL、没有计划日期的任务也在截止当天出现；同一任务因计划和截止同时命中时只显示一条，保留截止信息。当天截止与近期截止的聚合能力已确认，近期范围、具体分栏及呈现方式留待确定 |
| C27 | 除已安排的日清单外，支持查看 All list，主动回顾并重新安排任务 | 用户可从全部任务中挑出快到期或以前未完成的任务，再安排到具体日期/时段；不自动改写旧计划日期。「已逾期」「待重新安排」是否独立分栏、旧任务如何出现在今日视图等细节暂不冻结，留到页面设计与实际实现时评估 |
| C28 | 任务支持可选的预计时长，独立于具体执行时段 | 可在尚未安排日期/时段时估算工作量，不填不影响使用；预计时长不等于已安排时长或实际投入。汇总规则见 C29，拆分/合并时旧估算值如何保留仍需确定 |
| C29 | 父任务自动汇总最末级任务的预计时长 | 无子任务时可自行填写；有子任务时打平汇总末级任务，不重复加上中间父任务的估算。「不做了」排除计算；有末级任务未填时标明估算不完整，不把未知当作零。拆分后总估算可随末级任务变化 |

来源：本次产品讨论中用户关于任务内容、项目分类、多时段、父任务手动完成及两种不累积重复的明确表述。任务入口已替换为独立任务 MVP，正文勾选段落仍与独立任务库分开。

## 已接受的基本思路与暂定取舍

- 子任务可以只有标题和勾选状态；需要时再补备注和安排，使用上可作为轻量 checklist。不因为暂时没有时间，就强制转换成另一种对象。
- 第一版倾向省略标签，先满足项目与多级文件夹；标签解决跨项目维度，不能认定它被层级结构完全替代。
- 已确认提供独立、可选的预计时长，见 C28；预计投入、已安排时长与实际投入分开，实际计时不因时间段经过而自动产生。
- Inbox、手动排序、任务恢复等基本能力原则上认可，但默认归属、数据恢复期限和精确操作范围还未定案。

这些方向不表示已批准所有细节。助手提议的「下期子任务全部重置」「跳过本次」等，仍需结合完整规则确认，不能因“多数没问题”一并冻结。

## 后续迭代问题（不阻塞当前 MVP）

### 任务结构与完成

1. 已确认保留结构化子任务和备注检查项，后者不计入任务进度；是否可转换尚未确定，分区或混排留待页面交互设计。当前不涉及文档 Todo 聚合。
2. 已确认不限嵌套层数、每一级都有完整任务能力；移动携带完整子树，归属与防环规则见 C11。具体移动入口留待交互设计。
3. 完成、不做了和恢复的基本规则已定，见 C13–C16；涉及重复推进、后续编辑或跨设备并发时的撤销边界留待对应章节确定。
4. 状态、进度统计、结束后编辑/新增、不做了分支只读，以及删除/恢复、15 天回收站期限和缺失原位置的降级规则已定，见 C12、C17–C23；分母为零时的呈现、不做了分支中已有完成后代的统计、原位置存在但不可接收的恢复处理，以及项目归档行为仍需确定。

### 时间与汇总

1. 已确认无安排、仅计划日期、具体执行时段、DDL 逾期语义、当天/近期截止聚合、从 All list 主动回顾重排的流程，以及可选预计时长与末级汇总，见 C24–C29；具体分组与今日视图细节留到页面设计/实现时评估，不在当前逐项冻结。拆分/合并任务时旧估算值如何保留仍需确定。
2. 父任务自身时段与子任务时段重叠时，是覆盖关系还是额外工作；不能默认将汇总再求和。
3. 同一任务多个时段重叠、跨日、跨时区如何处理；拖动整项与移动某个时段分别改变什么。
4. DDL 仅日期和精确时刻的边界；子任务/时段超出父 DDL 时提示还是阻止，父 DDL 改变是否联动。
5. 已接入每条安排可选一个独立提醒时刻；无通知权限时可见提示，不自动启用通知。已完成/取消/删除任务撤销待发提醒；重启重建未来提醒，错过不补发。系统容量不足时保留最近提醒并提示。DDL 提醒、相对提前提醒和重复仍留待后续。

### 不累积重复

1. 固定周期漏掉多次后，完成或跳过是进入下一个未来日期，还是逐次处理漏期？是否记录跳过历史？
2. 固定日历规则下仅改本次安排是否保留原锚点；提前完成下次如何推进；同一天允许完成多次吗？
3. 完成后间隔按精确完成时刻还是本地日期计算；日历日与 24 小时、月底/闰年/夏令时如何处理。
4. 完成父任务后，下一期哪些子项重置、哪些备注保留、顺序如何保留；本期新增/删除子项是否修改重复模板。
5. 父任务重复时，子任务多段安排如何迁移到下一期；是否允许子任务独立重复，重复结束日与 DDL 如何区分。
6. 跳过、暂停、停止系列、删除本次/整个系列各自的状态与恢复；首版支持哪些。
7. 完成历史保存什么；撤销完成如何回退下一期、子项和通知；下一期已有新编辑时如何恢复。
8. 两设备同时离线完成只推进一次；删除和编辑冲突如何恢复。技术设计时落实，不以“对齐文档同步”略过。

### 组织与视图

1. 多级文件夹与项目清单是否分类型，哪些能直接放任务；项目可否完成或仅归档。
2. 未归类任务、项目内任务和子任务的归属与计数；父目录汇总是否包含全部后代。
3. 日清单和 All list 主动回顾重排的方向已定，见 C26–C27；Today、即将到来、已完成、搜索的具体筛选/分栏、父子上下文及多时段展示计数留到页面设计/实现时评估。
4. 自动排序、分组与手动顺序的关系；标签和优先级是否首版需要。
